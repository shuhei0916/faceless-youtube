# ADR-001: プロジェクト構造設計

## ステータス
承認済み

## 背景
前回のMVPでは単一ファイルにすべての機能が集中し、技術的負債が蓄積した。新しいプロジェクトでは関心の分離を徹底し、保守性の高いモジュラー構造を採用する。

## 決定事項

### ディレクトリ構造
```
src/
├── modules/           # 各機能モジュール
│   ├── faceDetection/ # 顔検出機能
│   ├── imageProcessor/ # 画像処理機能
│   ├── domHandler/    # DOM操作機能
│   └── configManager/ # 設定管理機能
├── content/           # コンテンツスクリプト
├── background/        # バックグラウンドスクリプト
└── popup/            # ポップアップUI

tests/
├── unit/             # ユニットテスト
├── integration/      # 統合テスト
└── e2e/             # E2Eテスト
```

### 設計原則
1. **単一責任の原則**: 各モジュールは明確に定義された単一の責務を持つ
2. **依存性の注入**: モジュール間の疎結合を維持
3. **テストファースト**: TDDサイクルに従い、テストを先に作成

## 影響
- 保守性の向上
- テストのしやすさ
- 機能拡張時の影響範囲の限定化
